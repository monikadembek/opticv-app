# CV Optimization Page — Section Help Information (Plan)

Planning notes for adding short, per-section explanations to the `cv-optimization` page,
so users understand what each section is, why it matters, and how ATS uses it.

## Recommended pattern

Reuse the existing info-dialog pattern already implemented in `export-footer.ts`/`.html`
(the "ATS Template Information" button): a small outlined `pi-info` icon `p-button` that
opens a `p-dialog` with explanatory text.

- Add this into `app-section-card`'s header (`section-card.ts` / `section-card.html`),
  next to the title, so every section gets it "for free" via new optional inputs
  (e.g. `helpTitle`, `helpBody`) — rather than re-implementing a dialog in each of the
  8 section components individually.
- **Dialog vs. tooltip:** the copy below is 2–4 sentences each — too long for a hover
  tooltip (`pTooltip`, already used in `keyword-gap.html` for short hints like
  "Importance"). Reserve tooltips for micro-hints on individual fields/badges; use the
  dialog for section-level "what is this and why does it matter" explanations.
- **Placement:** small circular outlined info icon button (`pi pi-info`, `rounded`,
  `outlined`, `severity="secondary"`, `size="small"`) placed in `section-card__header`,
  right after the title, before the status badge/collapse chevron — same visual
  treatment as the existing "ATS template information" button so it reads as one
  consistent affordance across the app.

## Proposed copy per section

**Job Posting**
> This is the job description you're optimizing your CV against. Everything below —
> keywords, ATS score, rewrites — is generated by comparing your CV to this specific
> posting, so the more complete the text you paste here, the better the suggestions.

**ATS Analysis**
> Applicant Tracking Systems (ATS) are software that many companies use to
> automatically scan and filter resumes before a human ever sees them. This score
> estimates how well your CV would perform in that scan — based on formatting,
> structure, and content match to the job posting. A higher score means your CV is
> less likely to get filtered out automatically.

**Keyword Gap**
> ATS software and recruiters scan for specific keywords (skills, tools, job titles)
> mentioned in the job posting. If your CV is missing terms the employer explicitly
> asked for, it can be scored lower or skipped entirely — even if you have the
> underlying experience. This section shows which important keywords from the job
> description are missing from your CV, so you can add the ones that genuinely apply
> to you.

**Summary Rewrite**
> Your professional summary is often the first thing an ATS parses and the first
> thing a recruiter reads. These rewritten versions are tailored to echo the language
> and priorities of the job posting, helping both the algorithm and the human
> reviewer quickly see you're a match.

**Bullet Upgrades**
> Strong, quantified bullet points (using action verbs and metrics) score better with
> ATS parsing and are easier for recruiters to skim. These suggestions rewrite your
> existing bullets — and propose new ones — to better reflect the responsibilities
> and keywords the job posting emphasizes.

**Cover Letter**
> A tailored cover letter reinforces the keywords and qualifications from your CV and
> directly addresses the job posting, which can help both ATS matching (some systems
> scan cover letters too) and human reviewers. Pick the variant that best fits your
> voice, then edit freely.

**Interview Prep**
> Based on the gap between your CV and this job posting, these are likely interview
> questions and talking points — helping you prepare answers that address exactly
> what this employer is looking for.

**LinkedIn Profile**
> Recruiters frequently cross-check LinkedIn profiles against CVs, and LinkedIn's own
> search also relies on keyword matching. These suggestions help align your LinkedIn
> profile with the same keywords and positioning used in your optimized CV.

## Implementation sketch (not yet built)

- Add `helpTitle = input<string>()` and `helpBody = input<string>()` (or a `ng-content`
  slot named `help`) to `SectionCard`.
- Render the info button + a `p-dialog` inside `section-card.html`, mirroring
  `export-footer.html`'s info button and "ATS Template Information" dialog markup.
- Pass the copy above as inputs from `cv-optimization.html` for each `app-section-card`
  usage.
- For richer content (e.g. Keyword Gap benefits from a short bullet list), allow
  `helpBody` to accept HTML/markup via `innerHTML` binding or a content-projection slot
  instead of a plain string, since some sections' explanations read better as a short
  paragraph + bullet list (like the existing ATS Template Information dialog).
