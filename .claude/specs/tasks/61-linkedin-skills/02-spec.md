# Task Specification

## Source

Azure DevOps Task: 61 — LinkedIn section: skills improvements

## Goal

Transform the LinkedIn Profile Boost "skills" output from a gap-only list of **new**
skills (`skillsToAdd?: string[]`) into a **single, complete, ranked, deduplicated
recommended-skills list** that merges the user's existing CV skills with new
target-role skills. Each entry carries an `isNew` flag so the UI can visually
distinguish CV skills from newly-suggested ones. The list is ranked by
recruiter-search relevance (most valuable first) and capped at LinkedIn's 50-skill
limit. The change spans the shared type, the backend AI prompt, the frontend
component + template, and the PDF/DOCX export service, and must remain backward
compatible with already-stored results.

## Context

LinkedIn Profile Boost is part of the CV optimization feature.

- **Shared type:** `LinkedInRewriteResult` in
  `packages/shared/datatypes/src/lib/datatypes.ts` (`skillsToAdd?: string[]`).
- **AI prompt:** persisted in the DB; seeded from
  `apps/opticv-be/prisma/seed.ts` under `PromptType.LINKEDIN_REWRITE`. The active
  version today is `v2.0.0`; resolved at runtime by `getActivePrompt` in
  `apps/opticv-be/src/app/ai/services/prompt.service.ts`
  (`findFirst({ where: { promptType, isActive: true }, orderBy: { createdAt: 'desc' } })`).
- **Frontend display:** `linkedin-updates` component (Section C "Skills to add")
  in
  `apps/opticv-web/src/app/features/cv-optimization/components/linkedin-updates/`.
- **Export:** PDF/DOCX generated by
  `apps/opticv-web/src/app/features/cv-optimization/services/linkedin-export.service.ts`
  (Section 3, uses `result.skillsToAdd ?? []` at two locations).

No backend **application** code references `skillsToAdd` / `LinkedInRewriteResult`
— the AI output is persisted and passed through generically — so the only backend
change is `seed.ts`.

## Scope

### In scope

- **Shared type** — add `RecommendedSkill` type; replace `skillsToAdd?: string[]`
  with `recommendedSkills?: RecommendedSkill[]` in `LinkedInRewriteResult`. Rebuild
  `@opticv/datatypes` (Nx `^build`) before dependent apps.
- **Backend prompt** — add a new `LINKEDIN_REWRITE` seed entry `version: '3.0.0'`,
  `isActive: true`; flip the existing `v2.0.0` entry to `isActive: false`. The
  v3.0.0 content changes the skills strategy (merge + dedupe + rank + cap 50 + flag
  new), the user-prompt template item, and the `submit_linkedin_sync` output schema.
  Run `npm run seed` to activate.
- **Frontend component** — `recommendedSkills` computed (defensively sliced to 50);
  `hasSkills` and `skillsCount` computed; `copyAllSkills()` action.
- **Frontend template** — replace Section C with heading "Recommended LinkedIn
  Skills", an `n / 50` count, a "Copy all" button, ranked chips (CV = blue, new =
  green with a "new" badge), and a "No skills recommended" empty state.
- **Export service** — PDF and DOCX Section 3 title → "Recommended LinkedIn Skills",
  render skills with a `(new)` marker for new skills, empty state "No skills recommended".
- **Unit tests** — update `linkedin-updates.spec.ts` to the new `recommendedSkills`
  shape; update `linkedin-export.service.spec.ts` if it references `skillsToAdd`.
- **Data cleanup** — delete the one existing stored LinkedIn optimization result
  from the DB before or after running the seed (no old-shaped data should reach the
  new code path).
- **Verification** — typecheck, lint, test, format, build; seed run; manual E2E.

### Out of scope

- Backward compatibility with previously-stored results. The one existing stored
  LinkedIn optimization result will be deleted from the DB; no legacy fallback is
  needed.
- Editing the body of the existing `v2.0.0` prompt (only its `isActive` flag flips).
- Changes to any other LinkedIn output sections (headline, about, experience,
  recommendations).
- Backend session/JWT validation or any AI pipeline changes beyond the seed prompt.
- Persisting `isNew` derivation on the backend beyond what the AI emits.

## Behavior

### Type

1. Introduce a shared object type:
   ```typescript
   export type RecommendedSkill = {
     name: string;
     isNew: boolean; // true = new gap skill; false = already in the CV
   };
   ```
   Placed near the other LinkedIn types.
2. In `LinkedInRewriteResult`, replace `skillsToAdd?: string[];` with
   `recommendedSkills?: RecommendedSkill[];`. The field stays **optional** for
   backward-compat with stored results.
3. Rename (not overload) so old vs. new stored data stay unambiguous. Ranking is
   encoded by **array order** (most valuable first) — no score field, matching the
   existing `sortedRecommendations` convention.

### Backend prompt (seed v3.0.0)

1. Add a new seed entry as a sibling of the v2.0.0 block: same `promptType`
   (`LINKEDIN_REWRITE`), `version: '3.0.0'`, `isActive: true`. Do **not** modify the
   v2.0.0 body.
2. Set the existing v2.0.0 entry to `isActive: false`. This is **mandatory** —
   `createdAt` is not refreshed on upsert-update, so relying on ordering alone is
   unreliable.
3. v3.0.0 content differences vs. v2.0.0:
   - **systemPrompt** — add a "Skills section strategy" block: start from the CV
     skills present in `<parsed_resume_sections>`, add target-role skills that are
     missing, dedupe case-insensitively, rank by recruiter-search relevance (most
     valuable first), cap at 50, set `isNew: true` for newly-suggested gap skills and
     `false` for skills already in the CV; never invent skills.
   - **userPromptTemplate** — replace the skills item (item 3) with a request for a
     "complete, ranked recommended skills list (merge CV + gap, dedupe, rank, max 50,
     flag new vs existing)".
   - **outputSchema** (`submit_linkedin_sync`) — replace
     `skillsToAdd: { type: 'array', items: { type: 'string' } }` with:
     ```typescript
     recommendedSkills: {
       type: 'array', maxItems: 50,
       items: {
         type: 'object', required: ['name', 'isNew'],
         properties: { name: { type: 'string' }, isNew: { type: 'boolean' } },
       },
     },
     ```
   - Leave the schema top-level `required` array unchanged (field stays optional).
4. Seed `main()` upserts keyed on `promptType_version`; the `update` branch writes
   `isActive`. Re-running `npm run seed` on an existing DB both deactivates v2.0.0 and
   activates v3.0.0 — idempotent, matching the existing v1.0.0(false)/v2.0.0(true)
   convention.

### Frontend component

1. Replace the current `hasSkills` computed with a set of computeds:
   - `recommendedSkills: computed<RecommendedSkill[]>` — returns
     `result().recommendedSkills?.slice(0, 50) ?? []`. The slice caps at 50 so the
     UI never exceeds the LinkedIn limit regardless of backend output. Array order
     (the AI's ranking) is preserved — no re-sort.
   - `hasSkills: computed` — `recommendedSkills().length > 0`.
   - `skillsCount: computed` — `recommendedSkills().length`.
2. Add `copyAllSkills()` that reuses the existing `copyToClipboard`, passing the
   comma-joined skill names: `recommendedSkills().map((s) => s.name).join(', ')`.
3. Angular 21 conventions: `OnPush`, signals/`computed`, `input.required`, no
   explicit `standalone: true`.

### Frontend template (Section C)

1. Heading → **"Recommended LinkedIn Skills"** with a `{{ skillsCount() }} / 50`
   count.
2. Add a **Copy all** `p-button` mirroring the existing copy button styling, wired to
   `copyAllSkills()`.
3. Render ranked chips over `recommendedSkills()`:
   - CV skills (`isNew === false`) → blue chips (`bg-blue-100 text-blue-800`).
   - New skills (`isNew === true`) → green chips with a small "new" badge (green
     convention matching the "Recommended" headline badge).
4. Empty state (`@if (!hasSkills())`) → **"No skills recommended"**.
5. Use `@for` with `track`, `@if`, `class` bindings (no `ngClass`/`ngStyle`).

### Export service

1. Import `RecommendedSkill` in the import block.
2. **PDF** (Section 3) — title → "Recommended LinkedIn Skills"; use
   `result.recommendedSkills ?? []`; render comma-joined names with a `(new)` marker
   appended to new skills; empty state "No skills recommended".
3. **DOCX** (Section 3) — same title; iterate `result.recommendedSkills ?? []`; emit
   a bullet per skill as `s.isNew ? \`${s.name} (new)\` : s.name`; empty state
   "No skills recommended".

## Edge Cases

- **More than 50 skills received** — the frontend defensively slices to the first 50;
  backend `maxItems: 50` should prevent this, but the UI must not exceed the cap even
  if the AI result violates it. The `n / 50` count therefore never exceeds 50.
- **Empty / undefined skills** — `recommendedSkills` empty/undefined resolves to `[]`;
  UI shows "No skills recommended"; exports show "No skills recommended".
- **Copy all with empty list** — button is absent (inside `@if (hasSkills())` block);
  not reachable by the user.

## Data / API

- **Type change:** `LinkedInRewriteResult.skillsToAdd?: string[]` →
  `LinkedInRewriteResult.recommendedSkills?: RecommendedSkill[]` (optional). New
  `RecommendedSkill { name: string; isNew: boolean }`.
- **DB:** no schema/migration change. Prompt data changes only via seed:
  - New `Prompt` row `LINKEDIN_REWRITE` `v3.0.0` `isActive: true`.
  - Existing `LINKEDIN_REWRITE` `v2.0.0` → `isActive: false`.
  - After seeding, exactly one `LINKEDIN_REWRITE` row has `isActive: true`.
- **AI output schema** (`submit_linkedin_sync`): `skillsToAdd` (string array) →
  `recommendedSkills` (array of `{ name, isNew }`, `maxItems: 50`). Top-level
  `required` unchanged.
- **No REST endpoint changes.**

## Assumptions

- The AI persistence/pass-through layer stores tool output generically, so no backend
  application code (services/DTOs beyond `seed.ts`) needs changing — confirmed by the
  absence of `skillsToAdd` / `LinkedInRewriteResult` references outside `seed.ts` on
  the backend.
- The one existing stored LinkedIn optimization result will be deleted from the DB
  before running the app with the new code; no old-shaped data will be present.
- Chip color conventions (blue for CV, green + "new" badge for new) follow existing
  component styling already in `linkedin-updates.html`.
- The "Copy all" and per-chip layout follow the existing copy-button pattern in the
  same template; no new PrimeNG components are introduced.
- Empty-state wording is standardized to "No skills recommended" across UI and both
  export formats.
